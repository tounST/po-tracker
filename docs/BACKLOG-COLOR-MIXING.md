# 🎨 ระบบบันทึกการผสมสี — งานค้าง (พักไว้ 2026-08-13)

> **สถานะ: พักไว้ตามคำสั่ง toun** — "เรื่องสีอันนี้ขอพัก แล้วเป็น list ที่ต้องทำภายหลังก่อนดีกว่า
> เรากลับมาทำเรื่องสต๊อกให้เสร็จกันก่อน" (2026-08-13)
>
> ไฟล์นี้เก็บ**ทุกอย่างที่คุยกันไว้แล้ว** เพื่อไม่ต้องเริ่มถามใหม่ตอนกลับมาทำ

---

## 1. ปัญหาที่ toun เล่ามา

โรงงาน**ผสมสีเอง** ไม่ได้สั่งสีผสมสำเร็จ (ตอบคำถามที่ค้างมาตั้งแต่ 2026-08-05)

- คนงานเป็นคนผสม ค่อย ๆ เติมทีละนิดตาม**สูตรจากโปรแกรมของ Nippon Paint**
- **ผสมแล้วเพี้ยนไปเรื่อย ๆ** — สูตรให้มาแบบหนึ่ง ของจริงออกมาอีกแบบ ต้องปรับแก้หน้างานทุกครั้ง
- ความรู้ทั้งหมดอยู่ในหัวคนผสม ไม่มีใครจดว่า "ครั้งที่แล้วเบอร์นี้ต้องเติมอะไรเพิ่มเท่าไหร่"
- toun อยากได้ **ข้อมูล + การผสม** อยู่ด้วยกัน: เติมไปเท่าไหร่ → ได้สีออกมาแบบไหน → ออกมาเป็นชาร์ตเทียบว่าเหมือน/ไม่เหมือนยังไง

---

## 2. ข้อเท็จจริงหน้างาน (toun ยืนยันแล้ว — อย่าถามซ้ำ)

| หัวข้อ | คำตอบ |
|---|---|
| **วิธีเทียบสี** | มี**เครื่องวัดสี (spectrophotometer)** วัดจริง **+ ดูแผ่นที่พ่นด้วยสายตา**ควบคู่กันเสมอ — ไม่ได้เชื่อเครื่องอย่างเดียว |
| **โปรแกรม Nippon** | **export ได้** — toun จะเอาไฟล์ตัวอย่างมาให้ดู (ยังไม่ได้ให้) |
| **เครื่องชั่ง** | **ไม่ได้ต่อกับคอม** เป็นเครื่องชั่งเดี่ยว ๆ อ่านค่าจากหน้าจอเอง |

**นัยสำคัญ 3 ข้อจากข้อเท็จจริงนี้:**
1. มีเครื่องวัดสีแล้ว = ได้ค่าตัวเลข (L\*a\*b\* / ΔE) มาเก็บได้จริง **ไม่ต้องซื้ออะไรเพิ่มเพื่อเริ่ม**
2. โปรแกรม export ได้ = สูตรตั้งต้นดึงเข้าระบบได้ ไม่ต้องพิมพ์มือ (รอดูรูปแบบไฟล์ก่อน)
3. เครื่องชั่งไม่ต่อคอม = **น้ำหนักต้องพิมพ์มือ** → ฟอร์มต้องออกแบบให้พิมพ์เร็วที่สุด ไม่งั้นคนผสมไม่บันทึก
   (ตรงกับหลักการเดิมของโปรเจค: *ระบบไม่ล้มเพราะบันทึกช้า แต่ล้มเพราะคนไม่บันทึก*)

## 3. ตัวแปรที่ทำให้สีเพี้ยน — ที่ "ไม่ใช่สูตร"

เรื่องนี้สำคัญมากตอนออกแบบ เพราะถ้าเก็บแต่สูตร จะสรุปผิดว่า "สูตรไม่ดี" ทั้งที่ปัญหาอยู่ที่การพ่น

จาก spec **Premila 8000 (metallic)**: ความหนาฟิล์ม **20–25 µm สูงสุด 30 µm**

- **ฟิล์มบางไป** → เกล็ดโลหะเรียงไม่สม่ำเสมอ สีดูอ่อน/ด่าง
- **ฟิล์มหนาไป** → เกล็ดจม สีดูเข้มกว่าที่ผสมไว้
- **ทินเนอร์ระเหยเร็ว/ช้า** ตามอากาศแต่ละวัน → เกล็ดตกตัวไม่เท่ากัน
- **ระยะ/แรงดัน/ความเร็วมือของปืนพ่น** → คนละคนพ่นสูตรเดียวกันได้คนละเฉด

👉 **ถ้าไม่เก็บตัวแปรพวกนี้คู่กับสูตร ข้อมูลจะสรุปอะไรไม่ได้เลย** — จะเห็นแค่ "เบอร์นี้บางครั้งผ่านบางครั้งไม่ผ่าน" โดยไม่รู้ว่าทำไม

## 4. โครงข้อมูลที่เสนอไว้ (ยังไม่ได้สร้าง)

ยึดหลักเดียวกับ `stock_movements` — **ledger ต่อท้ายอย่างเดียว ไม่ทับของเก่า**

### `color_formulas` — สูตรตั้งต้นจาก Nippon
| ช่อง | ความหมาย |
|---|---|
| `color_code` | เบอร์สี เช่น `202`, `554` |
| `car_brand` / `car_model` | ยี่ห้อ/รุ่นที่ใช้เบอร์นี้ |
| `base_formula` (JSONB) | `[{tinter, grams}, ...]` ตามที่ export มาจากโปรแกรม |
| `total_grams` · `source_version` | น้ำหนักรวม + เวอร์ชันสูตร (โปรแกรมอัปเดตสูตรได้) |

### `color_batches` — **การผสมจริง 1 ครั้ง = 1 แถว** (หัวใจของระบบ)
| ช่อง | ความหมาย |
|---|---|
| `formula_id` · `batch_no` · `mixed_by` · `mixed_at` | ผสมเบอร์อะไร ใครผสม เมื่อไหร่ |
| `actual_mix` (JSONB) | ที่ชั่ง**จริง**ทีละตัว — ไม่ใช่ตามสูตร |
| `corrections` (JSONB) | **ที่เติมเพิ่มทีหลัง** `[{tinter, grams, reason, seq}]` ← ตรงนี้คือความรู้ที่หายไปทุกวันนี้ |
| `lab_target` / `lab_actual` | ค่าจากเครื่องวัดสี `{L, a, b}` ของแผ่นเทียบ vs ของที่ผสมได้ |
| `delta_e` | ค่าต่างรวม (คำนวณให้อัตโนมัติ ไม่ต้องพิมพ์) |
| `visual_verdict` | สายตาคนตัดสิน: ผ่าน / ผ่านแบบฝืน / ไม่ผ่าน |
| `film_um` · `thinner_ratio` · `sprayed_by` · `temp_c` · `humidity` | ตัวแปรหน้างานจากข้อ 3 |
| `photo_url` | รูปแผ่นพ่น (bucket เดียวกับที่ทำไว้แล้ว) |

### สิ่งที่ระบบคำนวณให้ (ไม่ต้องพิมพ์)
- **ΔE** จาก L\*a\*b\* — ตัวเลขเดียวที่บอกว่า "ต่างแค่ไหน" (อุตสาหกรรมยานยนต์ทั่วไปรับที่ ΔE ≤ 1)
- **ชาร์ตเทียบ** ที่ toun ขอ = plot `a*` แกนนอน `b*` แกนตั้ง จุดเป้าหมาย 1 จุด + จุดของทุก batch → เห็นทันทีว่าเบอร์นี้ชอบเพี้ยนไปทางเขียวหรือทางแดง
- **สูตรแก้ที่แนะนำ** — พอมี batch เบอร์เดียวกันสัก 10-20 ครั้ง ดูได้ว่า "เบอร์ 554 ต้องเติมดำเพิ่มเฉลี่ย 1.2 กรัมเสมอ" → **เสนอตั้งแต่ครั้งแรก ไม่ต้องรอเพี้ยนแล้วค่อยแก้** ← นี่คือผลลัพธ์ปลายทางจริง ๆ ของฟีเจอร์นี้

## 5. ข้อควรระวังตอนกลับมาทำ

1. **อย่าเริ่มด้วยฟอร์มยาว** — คนผสมมือเปื้อนสี ถ้ากรอก 15 ช่องต่อหนึ่ง batch จะไม่มีใครกรอก
   เริ่มที่ **3 ช่องบังคับ** (เบอร์สี · เติมอะไรเพิ่มเท่าไหร่ · ผ่าน/ไม่ผ่าน) ที่เหลือเป็น optional ค่อยเพิ่มทีหลัง
2. **รอดูไฟล์ export จาก Nippon ก่อนออกแบบ `base_formula`** — รูปแบบไฟล์กำหนดว่าจะ import ได้ง่ายแค่ไหน
3. **ค่าจากเครื่องวัดสีต้องรู้ก่อนว่าเครื่องรุ่นไหน export ยังไง** — บางรุ่นต่อ USB ได้ บางรุ่นอ่านจากจอเท่านั้น (ยังไม่ได้ถาม)
4. **แยกไฟล์ใหม่ `color.html`** ตาม decision เดิมของโปรเจค — ห้ามยัดเข้า po-mobile/po-desktop ที่คนงานใช้อยู่ทุกวัน
5. เชื่อมกับสต๊อกได้ภายหลัง: ผสม 1 batch = เบิกแม่สีออกจากคลังอัตโนมัติ (ผ่าน `apply_stock_movement()`)
   ⚠️ แต่**ตอนนี้ในคลัง 15 รายการยังไม่มีแม่สีแยกตัว** มีแค่ "สีจริง / สีพื้น" รวม ๆ → ถ้าจะเชื่อม ต้องเพิ่มรายการแม่สีเข้าคลังก่อน

## 6. คำถามที่ยังไม่ได้ถาม (ถามตอนกลับมาทำ)

1. เครื่องวัดสี**ยี่ห้อ/รุ่นอะไร** ต่อคอม/export ไฟล์ได้ไหม หรืออ่านจากหน้าจออย่างเดียว?
2. ผสมกี่ batch ต่อวันโดยประมาณ? (กำหนดว่าฟอร์มต้องเร็วแค่ไหน)
3. สีที่ใช้บ่อยมีกี่เบอร์? (10 เบอร์ กับ 100 เบอร์ ออกแบบคนละแบบ)
4. คนผสมมีกี่คน — บันทึกด้วยมือถือของใคร?
